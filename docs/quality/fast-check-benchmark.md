# Быстрые проверки: замеры

Замер выполнен на синтетическом репозитории объёмом 10 000 строк в 51 файле, Linux 7.3.1, Intel i5-13600K (20 логических CPU). Кэши анализаторов и компиляторов, файловый кэш ОС и установленные бинарные файлы были прогреты. Время установки инструментов не входит. Замер описывает эту машину и не гарантирует такое же время на более медленном CI runner.

| Инструмент | Время | Решение |
|---|---:|---|
| Проверка ветки | 0,001–0,004 с | push |
| Gitleaks по исходящим коммитам | 0,379 с | push |
| Lizard CCN на изменённых файлах | 0,174 с | push |
| Ruff check | 0,020 с | push |
| Ruff format --check | 0,018 с | push |
| Prettier --check | 0,294 с | push |
| cargo fmt --check | 0,044 с | push |
| Clippy | 0,144 с | push |
| gofmt | 0,004 с | push |
| golangci-lint | 0,153 с | push |
| mypy | 0,626 с | MR |
| ESLint | 0,791 с | MR |
| tsc | 0,950 с | MR |
| dotnet format whitespace | 2,065 с | MR |
| dotnet format analyzers | 1,976 с | MR |

Pre-push набор запускает каждый инструмент, чей отдельный замер меньше 0,5 с; времена не суммируются для выбора класса. На том же наборе из 10 000 строк суммарный прогон занял 7,64 с. Замеры сделаны с прогретыми кэшами и установленными инструментами: клонирование, запуск runner и установка зависимостей в эти 7,64 с не входят. На CI runner с более медленным CPU суммарное время может отличаться. Версии измеренного toolchain перечислены в research-отчёте и закрепляются в CI-конфигурациях.

Lizard является общим CCN-гейтом и проверяет изменённые файлы `.cs` наряду с исходниками остальных поддерживаемых языков. В fast-наборе нет специфичных для C# форматтеров или анализаторов; `dotnet format` проходит в MR-классе.

Универсальный fast gate также запускает 18 коротких regression-тестов для CI scripts. Локальный прогон занял 0,087 с wall-clock (0,041 с внутри unittest); эта suite не входила в измерение суммарных 7,64 с выше.

Форматтеры работают на изменённых исходных файлах, кроме изменения project/config-файла, когда проверяется соответствующий проект. Clippy и golangci-lint анализируют затронутый crate/package, поскольку их диагностика зависит от полного контекста компиляции. Если изменён dependency/config-файл, анализ расширяется до соответствующего проекта. Все приведённые времена относятся к прогретым кэшам; cold-start и установка инструментов сюда не входят.
